# 严格审稿：不留情面地查论证，不攻击人

## 审稿格式

每条给“位置/短引文—等级—问题—为什么影响判断—所需证据或修改动作”。用用户自己的稿件时可标段号；公开样本避免大段复制。先抓最重要的至多5条，再给细节修订，避免几十个词汇替换淹没实质问题。

**P0 阻断交付**：与官方题目/限制/AI政策冲突；捏造个人贡献、结果、文献、合作/伦理许可；冒用别人经历；单位/学校错配造成误陈述；关键未确认占位混入最终稿。

**P1 内容薄弱**：只有领域没有问题；只有工具没有设计；把关联写成因果；既有工作与个人归属不清；方法不能回答问题；资源与时间不合理；过度承诺创新；PRE和RP机械重复。

**P2 表达与可读性**：不必要背景、空泛词、重复句尾、机械三项排比、格式不一致、长句关系不明。没有P0/P1时才把主要时间放在这里。

## 六维编辑自检（每项0–4，不做录取概率）

事实与归属、回应题目、研究推理、方法或行动具体性、可行性/边界、表达与规范。0=缺失或冲突，1=只有宣称，2=部分有据但有断点，3=证据和逻辑基本完整，4=具体且边界清楚。分数用于比较同一稿的修订，不经验证、没有统计预测含义，不能把总分换成录取率。任一P0未解决，不因其他项高分放行。

## 快速门（0–2）

在完整评分前先用六个问题决定是否能进入改写：`question / gap / method / feasibility / fit / experience-evidence`。0=缺失或与事实冲突，1=有方向但仍有断点，2=读者可以复述且证据边界清楚。任一关键项为 0 时只能交缺口、提纲或安全修改，不能称为 ready；快速门不是录取评分，也不替代下面的 P0/P1/P2 审稿。

## 六个刻薄但有用的检查问题

“把学校名换掉，这段还完全成立吗？”若成立，可能没有真实匹配。

“把技术工具名删掉，读者还知道你具体想比较什么吗？”若不知道，方法可能只有名词。

“这句话证明你作过研究判断，还是只证明你参加过项目？”PRE要从出席记录走向行动证据。

“你声称的结果，是方法能识别的结果吗？”访谈不能自动证明因果，模拟不能自动证明真实部署效果。

“如果数据权限拿不到，你的计划还剩什么？”没有备用路线就暴露关键依赖。

“一个面试追问就会露出是团队成果、未完成结果或不熟悉术语吗？”不能靠措辞掩盖能力边界。

## 批评后的修改顺序

先核验事实/规则→缩小问题→补齐证据与方法→调整篇幅→语言润色→精确计数/文件验收。能删除空话解决的问题就删除；需要事实的问题要追问，不能靠更强形容词修补。

最终再检查不同文书是否一致：日期、项目性质、学位状态、作者归属、研究技能、目标项目、导师名称。不要自动提交、联系导师或修改官方系统。
